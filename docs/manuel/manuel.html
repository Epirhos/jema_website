Chapitre 03

Installer le projet sur un ordinateur

Pour modifier le code, tester avant de publier, ou tout reconstruire depuis zéro.

Prérequis

  • Git : git-scm.com. Sous Windows, il fournit aussi « Git Bash ».
  • Node.js 22 LTS (minimum 20.3) : nodejs.org. Vérifiez avec node -v.
  • Un éditeur de code (VS Code conseillé).

Première installation

git clone https://github.com/Epirhos/jema_website.git
cd jema_website
git checkout bulle            # branche de test (main = production)
npm ci                        # installe exactement les versions de package-lock.json
npm run dev                   # site de travail : http://localhost:4321

Les commandes

CommandeEffet
npm run devSite de travail qui se recharge à chaque modification. L'admin et /telecharger/… n'y fonctionnent pas (voir ci-dessous).
npm run buildFabrique le site final dans dist/. À lancer avant chaque envoi : si ça échoue ici, ça échouera sur Cloudflare.
npm run previewSert dist/ pour vérifier le résultat final.
npm run sync:guideRecopie le mode d'emploi depuis l'app (chapitre 11).
npm run manuelRégénère ce PDF depuis docs/manuel/manuel.html.
node scripts/garde.mjs sourceLance seul le contrôle de sécurité des réglages et contenus (il tourne aussi automatiquement avant et après chaque npm run build).
Tester la fonction de téléchargement en localnpx wrangler pages dev dist (outil officiel de Cloudflare, téléchargé à la demande) sert le site avec la fonction /telecharger/…. Le plus simple reste l'aperçu de branche sur Cloudflare (chapitre 15).

Variables de construction

VariableRôleValeur
SITE_URLAdresse publique : liens canoniques, sitemaphttps://jema.app (par défaut)
BASE_PATHSous-dossier de publication/ (par défaut). Ne servait qu'à l'ancien hébergement GitHub Pages.
Windows et Git BashGit Bash transforme les chemins commençant par /. Pour tester BASE_PATH, préfixez : MSYS_NO_PATHCONV=1 BASE_PATH=/x/ npm run build.
Chapitre 04

Comment le site est construit

jema_website/
├─ astro.config.mjs          adresse du site, intégrations (React, Tailwind, sitemap)
├─ tailwind.config.js        configuration Tailwind (peu utilisée)
├─ functions/telecharger/[os].js  Cloudflare : /telecharger/windows|mac|deb|appimage
├─ public/                   copié tel quel dans le site
│  ├─ admin/                 l'administration (chapitre 12)
│  │  ├─ index.html          charge Sveltia + bouton « Mode d'emploi »
│  │  ├─ config.yml          rubriques et champs de l'admin
│  │  ├─ theme.css · preview.css · fonts/ · aide/
│  ├─ images/uploads/        images envoyées depuis l'admin
│  ├─ favicon.svg · robots.txt
├─ scripts/
│  ├─ sync-guide.mjs         copie le mode d'emploi de l'app
│  └─ manuel-pdf.mjs         fabrique ce PDF
├─ docs/manuel/              ce manuel (source + PDF)
└─ src/
   ├─ pages/                 une page = un fichier ; [slug] = page générée par contenu
   ├─ layouts/               Base (head, barre, bandeau, pied), Prose (texte), Listing (listes)
   ├─ components/            Navbar.jsx, Logo.jsx + astro/ (sections de l'accueil)
   ├─ content/               versions/, journal/, pages/, guide/ (Markdown)
   ├─ content.config.ts      schéma de chaque type de contenu
   ├─ data/                  site.json, downloads.json, banner.json, guide-parcours.json
   ├─ assets/captures/       captures de l'app (converties en WebP au build)
   ├─ lib/                   releases.js, downloads.js, url.js, format.js, rehype-base.mjs
   └─ styles/global.css      identité visuelle

Principes à respecter

  • Statique d'abord. Chaque page est du HTML lisible sans JavaScript. Les scripts ne font qu'améliorer (système détecté, version à jour).
  • Une source par information. Les réglages vivent dans src/data/, les textes longs dans src/content/, le mode d'emploi dans l'app. Ne recopiez pas une information à deux endroits.
  • Liens internes : dans un composant, passez par url('/chemin') (src/lib/url.js). Dans le Markdown, écrivez simplement /chemin.
Chapitre 05

Les contenus (Markdown)

Chaque contenu est un fichier texte : un en-tête entre deux lignes ---, puis le texte. L'admin écrit ces fichiers ; on peut aussi les écrire à la main.

TypeDossierChamps de l'en-têteAdresse
Nouveautéssrc/content/versionsversion (4.1.0), date, canal (bêta|stable), titre, resume, brouillon/nouveautes/4-1-0 (tiré du champ version)
Journalsrc/content/journaltitre, date, resume, categorie (Annonce|Coulisses|Conseil|Version), brouillon/journal/<nom du fichier>
Pagessrc/content/pagestitle, description, section (info|legal), updated/<fichier> ou /legal/<fichier>
Guidesrc/content/guideGénéré : ne pas modifier ici (chapitre 11)/guide/<fiche>

Exemple : une version écrite à la main

---
version: "4.1.0"
date: 2026-12-12
canal: bêta
titre: "Jema se souvient de vos chronologies"
resume: "Deux lignes sur ce qui change pour l'auteur."
brouillon: false
---

## Nouveau

- Ce que l'auteur peut faire maintenant.

## Corrigé

- L'export Word conserve les notes de bas de page.
  • Dates au format AAAA-MM-JJ. Mettez les textes entre guillemets s'ils contiennent « : ».
  • Un champ manquant ou mal écrit fait échouer la construction avec un message qui nomme le fichier : c'est voulu, rien de cassé n'est publié.
  • Les schémas sont dans src/content.config.ts. Ajouter un champ = l'ajouter là, dans public/admin/config.yml et dans la page qui l'affiche.

Chapitre 09

Captures de l'application

La visite de l'atelier montre de vraies captures de Jema. Une capture qui ne ressemble pas à l'application est pire que pas de capture : refaites-les quand l'interface change.

Le projet de démonstration

« L'Atelier de reliure » : 4 chapitres (La crue, Ilyès, Le registre, La clé), 5 personnages (Maëlle Guérin, Ilyès Benali, Armand, Lucienne Benali, Yves Guérin), 2 lieux, et une incohérence volontaire (le cahier de 1974 relié à Rennes alors que Lucienne était à Saint-Malo) pour montrer la Continuité. Il se trouve dans Documents/Jema Univers/L'Atelier de reliure.

Refaire une capture

  1. Ouvrez Jema (version installée), le projet de démonstration, fenêtre en 1440 × 900 (ou plein écran sur un écran de cette taille).
  2. Pour chaque vue et chaque thème (Clair, Sombre, Éditorial), capturez la fenêtre.
  3. Nommez <vue>-<thème>.png : ecrire-light.png, univers-dark.png, constellation-editorial.png…
  4. Déposez-les dans src/assets/captures/ (elles remplacent les anciennes), puis npm run build. Astro les convertit en WebP.

Ajouter une vue

Ajoutez une ligne au tableau VIEWS de src/components/astro/Tour.astro (id, label, caption) et déposez au minimum <id>-light.png. Une vue sans capture « light » est ignorée automatiquement.

Chapitre 10

Téléchargements et versions

Le site ne fabrique jamais les fichiers d'installation : il les trouve sur GitHub.

La chaîne complète

  1. Dans jema-editor_v2, un tag v4.1.0 poussé sur GitHub déclenche .github/workflows/build-app.yml : compilation Windows, macOS, Linux.
  2. Les fichiers sont publiés comme « Release » dans Epirhos/jema-releases (secret GH_RELEASE_TOKEN).
  3. Sur le site, chaque bouton pointe vers /telecharger/windows, /mac, /deb ou /appimage.
  4. La fonction Cloudflare (functions/telecharger/[os].js) lit la dernière Release publique (API GitHub, mise en cache 10 min) et redirige vers le fichier. Les Releases en brouillon ou « pre-release » sont ignorées.
  5. Si GitHub ne répond pas, elle reconstruit l'adresse depuis fallbackVersion. Si les téléchargements sont en pause, elle renvoie vers /#telecharger.

Noms de fichiers attendus

SystèmeRepéré parNom produit par electron-builder
Windowsfin en .exejema-editor-4.1.0-setup.exe
macOS.dmgjema-editor-4.1.0.dmg
Linux .deb.debjema-editor_4.1.0_amd64.deb
Linux AppImage.appimagejema-editor-4.1.0.AppImage
Ne changez pas ces noms à la légèreIls dépendent de name dans le package.json de l'app et d'artifactName dans electron-builder.yml. Si vous les changez, adaptez fallbackUrl() dans la fonction et fallbackUrls() dans src/lib/releases.js.

Publier une version : la liste

  • La CI de l'app (ci.yml) est verte ; l'app est testée en local.
  • Tag vX.Y.Z poussé ; la Release apparaît dans jema-releases avec les 4 fichiers (et les latest*.yml des mises à jour automatiques).
  • Admin → Nouveautés → nouvelle fiche X.Y.Z (le numéro doit correspondre).
  • Admin → Réglages → Version de secours = vX.Y.Z.
  • Captures refaites si l'interface a changé (chapitre 09).
  • Facultatif : bandeau « La version X.Y est disponible », article de journal.
  • Vérifier sur le site : les 4 adresses /telecharger/… donnent la nouvelle version.

Retirer une version défectueuse

Admin → Téléchargements → pause (le site explique). Puis sur GitHub, jema-releases → la Release → Edit → Save as draft : elle disparaît du site et des mises à jour automatiques de l'app, qui reviennent à la précédente Release publique.

Chapitre 11

Mode d'emploi de l'application

Une seule source : jema-editor_v2/docs/guide/. Le site en garde une copie, mise à jour par un script.

npm run sync:guide                                  # si les deux dépôts sont côte à côte
npm run sync:guide -- "C:\chemin\vers\jema-editor_v2"   # sinon
  • Recopie chaque fiche docs/guide/*.md vers src/content/guide/ et le sommaire _parcours.md vers src/data/guide-parcours.json.
  • Remplace les jetons [[id]] par le raccourci clavier lu dans src/renderer/src/lib/commands.js de l'app (affiché en touches).
  • Signale les raccourcis inconnus. Les fichiers générés sont enregistrés dans le dépôt : Cloudflare n'a pas besoin du dépôt de l'app.

À faire après chaque version de l'app qui modifie le guide, puis npm run build, commit, envoi.

Chapitre 12

L'administration (Sveltia CMS)

Une application web chargée par public/admin/index.html, qui lit et écrit les fichiers du dépôt par l'API GitHub. Aucun serveur à nous.

FichierRôle
public/admin/index.htmlCharge Sveltia (version épinglée 0.256.1 via unpkg), le thème, et ajoute le bouton « Mode d'emploi ».
public/admin/config.ymlDépôt et branche, rubriques, champs, aides, messages de commit.
public/admin/theme.cssHabillage aux couleurs du site (variables --sui-* + quelques sélecteurs).
public/admin/preview.cssMise en page de l'aperçu des contenus.
public/admin/aide/Mode d'emploi de l'admin (page HTML + captures). L'ouvrir sur la bonne fiche : la table SECTIONS d'index.html.

Ajouter un champ

  1. Déclarez-le dans src/content.config.ts (contenus) ou utilisez-le depuis le JSON (réglages).
  2. Ajoutez-le dans config.yml (name, label, widget, hint). Widgets courants : string, text, markdown, boolean, datetime, select, object, image.
  3. Affichez-le dans la page ou le composant concerné. Construisez, vérifiez, envoyez.

Mettre à jour Sveltia

Changez le numéro dans l'adresse du script (@sveltia/cms@0.256.1) et son empreinte integrity, sans quoi le navigateur refusera le script. Calcul de l'empreinte (Git Bash) : curl -sL <adresse> | openssl dgst -sha384 -binary | openssl base64 -A, à préfixer par sha384-. Testez sur l'aperçu de branche (chapitre 15) : connexion, ouverture d'une fiche, enregistrement. Si l'habillage se dégrade, c'est un sélecteur de theme.css qui a changé : l'admin reste utilisable, corrigez à loisir.

Banc d'essai sans jeton

Pour travailler l'apparence de l'admin sans toucher au dépôt : copiez public/admin dans un dossier de test, remplacez le backend de config.yml par name: test-repo, ajoutez dans index.html <link rel="cms-seed-url" href="/seed/manifest.json"> (un fichier {"files":["src/data/site.json", …]} à côté des fichiers à charger), servez le dossier et cliquez « Start Demo ». Les modifications restent dans le navigateur.

Connexion

  • Aujourd'hui : jeton d'accès GitHub (voir chapitre 02 et la fiche « Bien démarrer » du mode d'emploi).
  • Plus tard, bouton « Se connecter avec GitHub » : déployer le relais gratuit sveltia-cms-auth sur Cloudflare Workers (instructions sur github.com/sveltia/sveltia-cms-auth), créer une « OAuth App » GitHub pointant vers lui, puis renseigner base_url dans config.yml.
Chapitre 13

Sans cookie, sans bannière de consentement. Ne mesure que jema.app (attribut data-domains) : les aperçus et le site de travail ne faussent pas les chiffres.

Automatique : visites, pages vues, provenance (sites, campagnes UTM), pays, appareils, temps passé. En plus, ces événements :

  • Offre gratuite : 500 constructions par mois, bande passante illimitée, 100 000 appels de fonction par jour. Aucune carte bancaire nécessaire.

Relier jema.app (une seule fois)

  1. Cloudflare → Add a domain → jema.app, offre Free. Notez les deux serveurs de noms affichés.
  2. Name.com → My Domains → jema.app → Nameservers : remplacez les serveurs existants par ceux de Cloudflare.
  3. Attendez l'e-mail « jema.app is now active » (15 min à 24 h).
  4. Pages → jema → Custom domains → ajoutez jema.app puis www.jema.app. HTTPS est automatique (obligatoire en .app).

Chapitre 21

Sécurité et alertes

Objectif : qu'on ne puisse pas faire télécharger autre chose que Jema, détourner les messages des visiteurs, injecter du code ou faire tomber le site, et être prévenu de toute tentative.

Les protections en place

MenaceProtectionOù
Remplacer le fichier téléchargéLe navigateur ne connaît aucune adresse de fichier : tout passe par /telecharger/…. La fonction a le dépôt Epirhos/jema-releases écrit en dur et refuse toute adresse hors de github.com/Epirhos/jema-releases/releases/download/ (alerte si cela arrive).functions/telecharger/[os].js
Détourner les e-mails des visiteursLe site ne collecte aucune adresse : le contact ouvre la messagerie du visiteur vers editor.jema@gmail.com. Cette adresse est verrouillée dans l'admin et contrôlée à chaque construction ; toute autre adresse mailto: bloque la publication.scripts/garde.mjs
Injecter un script, un faux formulaire, un lien piégéLes contenus ne peuvent contenir ni script, ni cadre, ni formulaire, ni lien javascript:, ni lien vers un exécutable hébergé ailleurs : la construction échoue et rien n'est publié. Dans le navigateur, une politique de sécurité (CSP) n'autorise que les scripts présents à la construction et la mesure d'audience.scripts/garde.mjs, dist/_headers

La sentinelle est hors de portée d'un jeton voléSes valeurs attendues sont dans .github/workflows/sentinelle.yml. Un jeton d'admin (droit Contents) ne peut pas modifier ce dossier. Ne donnez jamais le droit Workflows au jeton de l'admin. La surveillance toutes les 6 h ne tourne que depuis main ; GitHub la met en pause après 60 jours sans activité sur le dépôt (un e-mail prévient, un clic la relance).

À régler une fois (dans les comptes)

  1. Double authentification sur GitHub, Cloudflare, Name.com, Umami et Gmail. C'est la protection la plus importante : presque toutes les attaques passent par un compte volé.
  2. Notifications push ntfy : installez l'application ntfy (Android, iOS) et abonnez-vous à un sujet long et secret, par exemple jema-alerte-7f3k9q2m. Ajoutez ensuite son adresse https://ntfy.sh/jema-alerte-7f3k9q2m dans Cloudflare (Workers & Pages → jema → Settings → Variables and Secrets → ALERTE_NTFY, type Secret) et dans GitHub (dépôt → Settings → Secrets and variables → Actions → ALERTE_NTFY).
  3. Notifications Cloudflare : Notifications → Add → Pages → « Deployment status », projet jema, évènements « Failed » et « Success » en production. Un déploiement que vous n'avez pas fait = alerte.
  4. Après le domaine : Security → WAF → Rate limiting rules → une règle « si le chemin commence par /telecharger/, plus de 20 requêtes en 10 s par IP → bloquer 10 s ». Activez aussi Security → Bots → Bot Fight Mode, et DNS → DNSSEC.
  5. Chez Name.com : vérifiez que le Transfer Lock du domaine est actif.
  6. Sur GitHub : Settings → Branches → règle sur main : interdire les « force push » et la suppression.

En cas d'alerte

  1. Si c'est vous (modification de code, réglage voulu) : fermez le ticket.
  2. Sinon, dans l'ordre : Cloudflare → Deployments → Rollback vers la dernière version saine ; révoquez le jeton de l'admin ; changez le mot de passe GitHub et vérifiez Settings → Sessions et Security log ; mettez les téléchargements en pause si un fichier est en cause.
  3. Annulez le commit fautif (GitHub → le commit → Revert), puis recréez un jeton.

Changer légitimement une valeur verrouillée

Par exemple une nouvelle adresse de contact : modifiez-la dans src/data/site.json, dans ATTENDU de scripts/garde.mjs et dans env de .github/workflows/sentinelle.yml (et dans la fonction de téléchargement s'il s'agit du dépôt des versions). La sentinelle ouvrira un ticket : normal, fermez-le.

Limite honnêteRien ne protège contre quelqu'un qui contrôle à la fois votre compte GitHub et votre compte Cloudflare : d'où la double authentification. La meilleure garantie pour les utilisateurs reste la signature numérique de l'application (Windows et macOS), à prévoir pour la version stable : un fichier modifié ne serait alors plus reconnu comme venant de vous.
